# RQ1 예비 측정 — 가중치 공유의 메모리 이득 (프로세스 수준, Pi4)

사이드채널(RQ2) 예비 실험의 관측 도구가 신호를 못 잡는 구조임을 확인한 뒤(RESULTS.md 참고),
Pi4는 기획안의 RQ1·RQ4(메모리 비용) 쪽으로 돌려 측정했다. 이 측정은 benign한 RAM 계측이다.

## 방법
- 모델: Qwen2.5-0.5B Q4_K_M (`pmem-model-root/model.gguf`), llama.cpp CPU 텍스트 경로.
- 정책 A(완전 분리): `-lm none` — 모델을 프로세스 전용 메모리로 읽음.
- 정책 B(전체 공유): `-lm mmap` — 읽기 전용 모델 파일을 mmap, 두 인스턴스가 페이지 캐시 공유.
- 지표: `/proc/PID/smaps_rollup`의 PSS 합으로 N개 인스턴스의 고유 물리 메모리를 셈
  (공유 페이지는 공유자 수로 나뉘므로 sum(PSS)=실제 물리량). Δ=M(2)−M(1).
- 두 인스턴스는 서로 다른 물리 코어(2,3)에 고정. `tools/ram_measure.py`.

## 결과 (3회 반복)
| 런 | Δ_A 분리 (MiB) | Δ_B 공유 (MiB) | 절감률 |
|---|---|---|---|
| 1 | 538.4 | 78.4 | 85.4% |
| 2 | 542.0 | 156.3 | 71.2% |
| 3 | 540.0 | 77.3 | 85.7% |

- Δ_A(분리) = **540.1 ± 1.8 MiB** — 매우 안정적. 2번째 인스턴스가 모델을 통째로 또 올림(PrivDirty ≈ 538 MiB).
- Δ_B(공유) = 두 번은 ~77–78 MiB, 한 번은 156 MiB. **중앙값 ~78 MiB.**
- **물리 공유의 직접 증거**: 정책 B의 두 인스턴스 모두 `Shared_Clean = 475.8 MiB`로 일관.
  이게 공유되는 모델 본체이고, PSS가 절반씩 나눠 가짐(각 ~312 MiB).

## 해석
- 가중치 공유는 2번째 인스턴스의 메모리 비용을 **538 MiB → ~78 MiB로, 약 85% 절감**한다.
  남는 ~78 MiB는 공유 불가능한 인스턴스 전용 부분(KV 캐시, compute 버퍼, 런타임)이다.
- **엣지 ARM(Pi4)에서도 공유 이득이 성립**함을 보임 → 기획안 RQ1·RQ4 방향을 뒷받침.
- 이건 프로세스 수준 예비 측정이다. 본실험에서는:
  - 같은 부하 지점(고정 토큰 수·동일 생성 단계)에서 재서 Δ_B 변동을 줄인다.
  - 사전 등록한 표본 수로 반복하고, 정책 A/B/C/D/F를 같은 환경에서 비교한다.
  - KSM off 확인, lazy 로딩(-lzm) off 고정, PSS·파일 캐시 대조로 같은 페이지 한 번만 센다.
  - MicroVM 수준(virtio-pmem DAX)에서도 같은 측정을 반복해 호스트 실제 매핑과 대조.

## Δ_B 변동 원인 (메모 )
156 MiB 이상치는 측정 시점이 2번째 인스턴스의 KV/compute 버퍼 할당 구간과 겹친 것으로 보인다.
본실험에서는 생성 단계를 고정한 뒤 측정하면 사라질 것으로 예상(검증할 항목).
